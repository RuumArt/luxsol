# luxsol.sk

Интернет-магазин спортивных и защитных сетей на 1С-Битрикс.

## Код

- `www/local/php_interface/room/` — бизнес-логика в пространстве имён `Room`: цены, корзина, доставка, уведомления, аналитика.
- `www/local/templates/luxol/` — шаблоны и ресурсы интерфейса.
- `www/local/components/` — собственные компоненты Битрикса.
- `www/ajax/` — обработчики запросов интерфейса.
- `www/local/tools/` — инструменты диагностики и обслуживания.
- `scripts/deploy.sh` — выкладка по SSH/rsync; без `--apply` показывает предварительный просмотр.

## Окружение и секреты

Локальный стек: PHP 8.3, Nginx, MySQL, Traefik. `docker-compose.yml` использует общую инфраструктуру родительского проекта `bitrix-sites`: сеть, конфигурацию PHP, cron и почты. Сам по себе этот репозиторий не содержит полного Docker-окружения.

Для новой копии нужны:

1. Совместимое ядро Битрикса в `www/bitrix/`, база данных и пользовательские файлы в `www/upload/`. Они не хранятся в Git.
2. Локальный `.env`, подготовленный по `.env.local.example` или `.env.server.example` с собственными значениями.
3. Зависимости PHP: `cd www/local && composer install`.
4. Настройки интеграций: скопировать `www/local/php_interface/room/settings.local.example.php` в `settings.local.php` и заполнить локально. Альтернатива — переменные окружения с такими же именами констант. Локальный файл имеет приоритет.
5. Ключи и сертификаты GP WebPay, а также параметры шлюза в настройках платёжной системы Битрикса. Ключи передаются отдельно от Git.

Файлы окружения, секреты, дампы, резервные копии и внутренние бизнес-отчёты исключены из Git. Публичный ключ reCAPTCHA в клиентском JavaScript доступен посетителям по назначению; секрет проверки хранится только в локальных настройках.

## Проверка оплаты

```sh
docker exec luxsol-sk-php-fpm php -d xdebug.mode=off /var/www/scripts/tests/gpwebpay-response.php
```

Проверки используют временные RSA-ключи и заглушки Битрикса, без реальных платежей, HTTP-запросов или записи в базу. Обработчик проверяет обе подписи GP WebPay, магазин, платёж и номер сохранённой платёжной попытки.

## Выкладка

Перед первой выкладкой этой версии на существующий сервер перенести его секреты из старого `room/settings.php`, `init.php` и `Room\Tools\Order` в локальный `room/settings.local.php`. Не заменять серверные значения локальными ключами. Скрипт сохраняет этот локальный файл и каталог ключей GP WebPay.

Изменения вне `www/local/` нужно передавать явно: по умолчанию скрипт выкладывает только `local/`. Например, изменение `init.php` находится внутри этого каталога, а изменение `ajax/add_cart.php` нужно указать отдельно.

Перед выкладкой изменений оплаты проверить полный платёжный цикл в тестовом окружении GP WebPay.

## GitHub Actions

`.github/workflows/deploy.yml` запускает проверки PHP 8.3 и 8.4, установку зависимостей из lock-файла и 35 проверок оплаты. После успешных проверок изменения `www/`, `scripts/` или самого workflow, отправленные в `main`, автоматически выкладываются на сервер. Запуски сериализованы: новая выкладка не прерывает текущую.

В окружении GitHub `production` используются переменная `DEPLOY_HOST` и секреты `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`. SSH-ключ отдельный; аккаунт `luxsol-deploy` принимает только ограниченный rsync в промежуточный каталог и четыре фиксированные команды выкладки. Доступ к интерактивной оболочке и проброс портов запрещены. Разрешена только ветка `main`.

Выкладка основана на ручном скрипте: архив текущих затрагиваемых каталогов в `/root/deploy-backups`, rsync без удаления серверных файлов, владелец `www-data`, очистка кеша Битрикса и проверка HTTP-ответов. CI отправляет все отслеживаемые файлы `www/` и установленные зависимости `local/vendor/`; ядро, загрузки, ключи, серверные настройки и данные обслуживания сохраняются. Ошибка передачи останавливает workflow. Ошибка проверки сайта вызывает восстановление архива и красный статус workflow.

Ручной запуск в Actions по умолчанию делает предварительный просмотр (`dry_run: true`), включая проверку синтаксиса на сервере, без изменения рабочих файлов сайта. Для выкладки выбрать `dry_run: false`. После выкладки нового коммита будут проверены главная, каталог, контакты, корзина и страница оформления; это HTTP-проверка, которая не создаёт настоящий заказ.

Серверные помощники `scripts/ci/server-release.py` и `ssh-entrypoint.py` устанавливаются администратором в `/usr/local/sbin/luxsol-ci-release` и `/usr/local/sbin/luxsol-ci-ssh`. Workflow не заменяет их автоматически. `migrate-server-settings.py` выполняет первоначальный перенос серверных секретов без вывода их значений и без замены настроек значениями с компьютера разработчика.
